## Not done / deviations

* **Source-side query logs** (e.g. `pg_stat_statements`) are not mined: only the platform's own
  `query_execution` audit. Reading a source's statistics views is a data-touching step outside the
  selected assets, which the crawler invariants forbid; it can come later as a gateway-governed
  capability.
* **PDF**: `pypdf` is an optional extra (`documents`, declared, not installed here — disk budget), so
  only the built-in extractor ran in these tests; it reads simple-font PDFs only (tested with fpdf2
  output). The `pypdf` path is untested in this session.
* **Attested Computation profile** is self-checked (`check_attested`): OKF publishes no JSON Schema.
  `parameters: []` (a finding is a fixed computation) and the `executor`/`attester` resources are
  `analystos://` URIs, not runnable references, by design (import never executes).
* **No migration**: everything persists in existing tables (pack revisions, `crawl_run.stats`,
  lineage edges, audit, run events). Two event types added: `crawl.facet_failed`, `knowledge.ingested`.
* The crawler's `context_entry` table rows are replaced by pack `Table` documents (retrieval now
  finds crawled tables through the knowledge index); old rows are deleted as each table is re-crawled.
* Open with P4-K07: a table description approved in the review queue is written to
  `catalog/<asset id>.md`, while the crawler writes `tables/<schema.table>.md` (draft). Both are
  `type: Table`, so a reviewed table can appear twice in retrieval; the approved text also reaches
  the crawler document through the catalog on the next crawl. Unifying the two paths is left for a
  follow-up.
